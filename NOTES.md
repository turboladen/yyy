# Projects

I want to be able to capture the original "recipe" for a project, like the Stompbox tester, for
example, then apply interesting variations to that (which may even be suggested in the recipe). For
example, the Stompbox Tester needs 4 banana male -> alligator wires--you could do the project with all
those being 1 color, OR you could follow the color scheme they suggest: red, black, blue green. In
this case, the "archetype" could capture that only 4 black wires are needed, but as an alternative,
you could use 1 red, 1 black, 1 blue and 1 green wire.

Next, when you want to start in on figuring out what you want for a project, you base it on an
archetype. This gives specific items/components to use.

Then, when you go to build the thing, you do a "build". A build is directly related to a project,
where there can be many builds of the same project. If you need to change the recipe of the project,
you need to create a new project that the build can relate to.

- Project Archetype: the original "recipe" that I found from some source (book, website, etc).
  - Parts that are related here can be given as generic (ex. 4 banana male -> alligator vs. 1
    package of Jameco banana -> alligator wires) _or_ specific (Part #1234 from mouser.com).
  -
- Projects: Variations (or the same as) of the archetype, but still analogous to a recipe. Many of
  these can relate to an archetype.
- Build: The actual, point-in-time build of a project.
